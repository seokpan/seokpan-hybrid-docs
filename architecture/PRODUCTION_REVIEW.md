## 1. 제작 범위와 상태

사용자의 “오케이. 계속해서 이어지는 후속 작업들을 진행해줄래?”를 이전 제작 계획에 따른 이미지 제작과 저장소 반영의 지시로 적용했습니다. 전체 논리·물리 2장의 자체 시각 검증을 먼저 수행하고 상세 10장을 이어서 제작했습니다. 이 진행 요청을 새 기술/자원 선택, 실제 환경 적용 또는 사용자 최종 그림 승인으로 확대하지 않습니다.

모든 그림에 설계 목표·구현/시험 미확인·설계 기준일·제작일·근거 절·확인 대기 입력을 표시합니다. 예비 주소를 생성 Subnet으로, 규모 후보를 실제 구축으로, 시험 목표를 달성값으로 표현하지 않습니다. 정확한 도형·글자·연결을 관리하기 위해 SVG 벡터 원본과 동일한 내용의 PNG 출력을 사용했습니다. 장식용 생성 이미지나 제품 로고는 추가하지 않았습니다.

## 4. 파일 검증과 표시 범위

- 00~04 원문 5개의 바이트 수/SHA-256은 [Source Manifest](../design/source-manifest.json)과 동일합니다. 원문의 설계 진실성이나 Runtime 성공까지 증명하는 검사가 아닙니다.
- SVG 12개의 XML·제목/설명·출처/대기 입력·외부 리소스 비의존·포함 글꼴의 사용 문자 Glyph를 확인했습니다. 공개 텍스트의 고위험 비밀정보 패턴 검사 일치는 0건입니다.
- PNG 12개를 폭 3600px로 완전 Decode했습니다. 물리 그림은 3600×2800, 나머지는 3600×2400입니다. 수정된 SVG와 PNG의 내용을 직접 대조했습니다.
- PNG 12개를 개별 확인했으며 수정된 그림을 다시 확인했습니다. 단순 접속/역할 배치 그림은 패널·계층으로, 흐름은 필요한 연결선으로 표현합니다. 구현 완료 상태를 추정하는 실측값은 넣지 않았습니다.
- GitHub 브라우저의 SVG 렌더링을 직접 확인하지 않았습니다. README는 검증한 PNG 미리보기와 SVG 링크로 구성합니다. GitHub 표시 확인은 별도이며 현지 설치 글꼴의 Inkscape 렌더와 모든 SVG Viewer의 동작을 동일시하지 않습니다.
- [생성 코드](tools/build_diagrams.py)와 [검증 코드](tools/verify_diagrams.py), [글꼴 출처/라이선스](assets/README.md)를 보존합니다. 새 파일과 수정 문서의 상대 링크를 검사합니다. 원격 Git blob과 로컬 파일의 동일성은 PR 등록 후 다시 대조합니다.

## 5. 중단 후 재개 검증 — 2026-10-02 KST

중단 후 SVG/PNG 12쌍과 생성/검증 코드, 목차·Manifest가 남아 있음을 확인했습니다. 원격 PR #3에는 아직 제작 계획 단계의 10개 파일만 있었으므로 로컬 제작 완료와 원격 등록 완료를 구분해 마지막 검증·등록부터 재개합니다. 새 그림을 중복 생성하지 않습니다.

사용자 질문에 따라 제작 계획 §5.1에 승인 구조·실제 AZ/Host 배정 대기·초기 규모 후보·Runtime 배치·시험 성과를 구분하고 결과판 작성 시점을 기록했습니다. 승인된 ROSA 모델·VPC/Subnet 구조를 후보로 되돌리지 않습니다. 관련 배치 증거가 확인되면 05 전체 종료 전에도 결과판을 작성할 수 있으며 일부 확인값으로 중간 결과판도 가능합니다. 구축 배치 확인을 HA/DR 시험 PASS와 구분합니다.

원문 동일성·12쌍 파일 검증·문서 링크를 다시 확인하고 원격 Tree의 Git blob SHA를 로컬 파일과 대조합니다. 이 재개 검증의 범위는 산출물과 저장소이며 실제 ROSA/On-Prem 환경 조회나 자원 생성은 포함하지 않습니다.

## 6. PR #5 이후 병합 전 통합 확인 — 2026-10-02 KST

PR #5가 먼저 병합된 main `333ac66780960ab68b708f249d9870d1e3246b52`와 그림 제작 Head `96999d33a90f689a809bab30db4a667391c4a564`를 대조했습니다. #5는 `execution/`·`evidence/`의 10개 파일 추가이며 #3의 기존 변경 경로와 겹치지 않습니다. GitHub는 #3의 병합 가능 상태를 보고했고, 해당 Head의 CI Status/Check Run은 등록 0개였습니다. 자동 CI 통과로 표현하지 않습니다.

루트 README의 당시 ‘05 미포함’ 안내를 이미 공유된 실행 안내·단일05·진행표·인계·Evidence 링크로 갱신하고, 설계 목차에서 05로 연결했습니다. 현재 안내의 그림 검토와 PR 병합을 분리해 병합 뒤에도 사용자 그림 의견·실제 구축 결과판 대기 상태를 정확히 표시합니다. 제작 전 검토 이력의 당시 조회 결과는 보존합니다.

main의 공유 파일 10개를 같은 Git blob으로 통합하고 승인 원문 5개·SVG/PNG 12쌍은 변경하지 않습니다. 병합 전 파일·링크 검증과 병합 후 main Tree에서 이 파일들의 동일성을 확인합니다. 이 통합은 구현/시험/발표의 진행 상태나 담당자 Actual을 변경하지 않습니다.

## 7. DR 목표 개정과 그림 10 재검증 — 2026-10-05 KST

RTO 10분·영속 DB RPO 30분·운영 중 Portable Backup 15분 주기를 설계·시험 요구사항으로 반영합니다. 일반 7일 보존·마지막 검증본 보호와 Cloud Primary + On-Prem Backup/Restore, 별도 전용 DB VM·새 Redis·사전 자산 구조는 유지합니다. 최초 제작/2026-10-03 재검토 기록의 30분·90분·1시간은 당시 이력이며 새 수치의 달성 근거로 바꾸지 않습니다.

생성 원본의 백업 주기·복구 목표 및 그림 10의 개정 출처를 수정해 해당 SVG/PNG만 재생성했습니다. PNG를 직접 열어 주기·RTO/RPO·경로·화살표·문자/여백을 확인하며, 설계 목표/구현·시험 미확인·아직 달성값 아님 표시를 유지합니다. 다른 11개 SVG/PNG는 현재 원격 main의 바이트 수·SHA-256과 동일하게 보존합니다. 폰트 글리프·SVG XML/텍스트·선언된 경계·PNG 전체 Decode/3600×2400 크기와 출처 식별을 다시 검증합니다.

이 개정은 설계 산출물의 정합 확인입니다. 로컬 부분 예행의 DB/Backend 결과를 기존 전체 T18 PASS·실제 사용자 복구 시간·Cloud 백업 최신성으로 확대하지 않습니다. 실제 Storage/Key·도구/버전·Image/Manifest·접속 경로와 재시험의 증거는 관련 Run에 연결합니다.
