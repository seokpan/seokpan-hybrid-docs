## 이슈 처리와 다른 담당 범위

- B 전용 실행 이슈 Docs21·Infra25·GitOps10·App4는 범위 재결정에 따른 종료(`not_planned`)로 닫는다. 완료한 실행을 실패로 바꾸거나 원 복합 조건을 모두 충족했다고 체크하지 않는다.
- Docs6(팀 발표 후보)·Docs8(팀 접근/인계)은 B 범위 완료와 팀 범위를 명시하고 전체 이슈를 대신 닫지 않는다. 최종 발표/인계 수락을 새로 확인했다는 뜻이 아니다.
- 다른 담당 소유 Infra17/46 및 D App47에서는 B와 관련된 미확인/완료 조건의 종료 처분만 연결한다. 다른 담당 체크·자원·외부 자격·계정 전체 청구를 B가 완료하지 않는다.
- 병합된 Docs101·App43의 미수락 조건도 추가 실행 대기가 아닌 미수행/제외 종료로 정리한다. 닫힌 이슈/PR을 재개하지 않는다.
- VM 자체 폐기 방침에 따라 VM 내부 키/보호 파일 개별 폐기를 B 종료 조건에 추가하지 않는다. 외부 계정 자격·DB/SMTP/실데이터와 최종 청구의 다른 Owner 완료는 미확인으로 유지한다.

## 실제 남은 순서

1. 최종 종료 처분 문서/현재 안내를 네 기존 PR에 반영한다. Source·실제 결과·원본은 보존한다.
2. 각 최종 head의 CI와 리뷰 요청 상태만 확인하고 필요한 리뷰 요청을 전달한다. 완료 런타임 검사는 다시 실행하지 않는다.
3. 사용자가 네 PR을 검토·병합한다. 병합 전에는 main 반영 완료라고 표시하지 않는다.
4. 미수행 시험·영상·Recovery·전체 정산을 이유로 B 자원 생성이나 시험을 다시 시작하지 않는다.

## GitHub 종료 반영 방식

기존 본문8곳에는 종료 판정을 추가하고, 큰 기존 본문을 다시 게시하지 않는3곳(Docs8/101/21)은 내부 정보가 없는 종료 판정 댓글로 연결했다. B 전용4개 이슈는 범위 재결정 종료이며 팀/다른 담당 이슈 상태는 유지했다. 기존 공개728체크 원장은 원 링크로 참조하고 새 게시물은 분류 수와 최종 처분 규칙만 기록한다. 개별 원문·접속 정보·153KB 개별 원장은 새 커밋에 포함하지 않는다.
