# Handover Template

아래 제출 양식을 해당 작업 Issue의 결과 댓글/본문에 사용하고 수신자는 그 기록에서 확인합니다. 입력 제공만인지 실제 실행까지 했는지 범위를 적습니다. 진행표에는 해당 기록 링크와 개정/인계 상태만 연결합니다. 이것은 빈 양식이며 실제 결과가 아닙니다.

## Provider

- 작성 담당 / 실제 작성자·수행자 / Reviewer:
- 대표 작업 Issue / 관련 PR·Run:
- 승인 근거 절 / I01~I07 해당 항목:
- 대상·환경 / 코드·입력·실제 실행 포함 범위:
- 전체 Source SHA / 입력·도구·설정·Schema·Secret 개정의 해당 항목:
- 필요한 비민감 값 / 보호 원본 논리 참조와 제공자:
- 완료한 범위 / 미확인·남은 범위:
- 검사·실행 판정 / 증거·실패·환경 차이:
- 실제 시각 / 측정 소요·비용 또는 미측정:
- 현재 Lock·부분 자원·잔존 상태 / 정리·복구 책임:
- 결과 수신자 / 필요한 확인 시점:
- 직접 막히는 후속 작업 / 계속할 독립 준비:

## Receiver

- 확인자 / 확인 시각:
- 받은 개정 / 대상·접근 확인:
- 수락 / 일부 범위 수락 / 보완 요청 / 보류:
- 사용할 범위 / 아직 막히는 후속 실행:
- 보완 사유·담당 / 재제출 조건·다음 확인:
- 연결한 후속 Issue·PR·Run:

## Checks

누락·오래된 개정·잘못된 대상·환경 차이 미설명·원본 접근 불가·민감값 노출·부분 실패 은폐·Owner 충돌은 보완/보류 사유입니다. 인계 수락은 후속 실행 성공과 다릅니다. Secret·Token·평문/전체 State/Plan·SQL/Backup·상세 보호 접속정보를 공개 기록에 넣지 않습니다.
