## 연쇄 추적 방법과 판정

1. 작성/배정/참여/언급 기록에서 원 이슈·PR·리뷰·실행 증거를 연결했다.
2. PR의 과거 요청 변경과 이후 승인·병합을 구분했다. 병합 전 본문·옛 댓글을 현재 대기 조건으로 사용하지 않는다.
3. 문서는 설계 목표, Source/실행 계약, 날짜가 고정된 실행 증거, 최신 상태 안내로 구분했다. 승인 Source·후보·Apply·실제 업무·다른 담당 실행을 서로 승계하지 않는다.
4. 완료 결과를 전체 원 조건과 대조했다. 단일 부분 성공으로 복합 체크를 올리지 않았고 원 이력·실패·작성자·수치는 보존했다.
5. 변경본을 기준으로 링크·현재 상태·언어·TH 집계·역할/범위와 보존 파일 참조를 다시 검사했다. 새 오류가 나오면 그 보완만 적용하고 다시 대조한다.

이는 기록·상태·참조의 전수 대조다. 모든 코드의 기능·성능·보안 재인증이나 모든 과거 로그의 독립 재실행 검증이 아니다. Source·설정·선언·코드 테스트는 재실행하지 않았으며 실제 자원에도 접근하지 않았다.
